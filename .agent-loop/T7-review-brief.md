# 최종 통합 검토

작업 폴더는 `rehearsal-20260922`, 기준 커밋은 `57e50ea`다. 원본 폴더의 코드, 운영 DB, 원격 저장소는 수정하지 않는다. 계획과 결과 문서, 단계별 구현/독립 시험/검토 기록을 먼저 읽는다. tracked diff에 빠지는 새 파일도 포함한다.

T1~T5의 승인 이후 변경 경계에서 새로 생긴 중대한 결함을 확인한다. 이미 기록한 실물 미검증·접근 불가를 코드 결함으로 다시 등록하거나 같은 전체 시험을 이유 없이 반복하지 않는다.

1. 지팡이 새 RSSI Notify → 앱 MTU 협상 → 현재 타깃 표본 → 자동 탑승 → STOP/해제까지 계약 연결. 규칙은 -60dBm/7초를 유지한다. 초기 NONE 상태 공백 및 실제 RF 시험 한계는 명시한다.
2. Provider 위치 추적이 Riding→Alight 뒤에도 유지되고 TRIP_DONE 완료 음성에 response ID/실제 출력 종료를 대응한다. 늦은 응답·로컬 음성 대체·취소·다음 운행 경합이 terminal 상태를 복원하지 않아야 한다.
3. 하차벨은 물리 재전송과 결과 저장 재시도를 구분한다. T3 원자적 RPC의 최초 결과 우선, legacy 복구, CANCELLED/TRIP_DONE 보존 및 service_role 권한이 모바일 오류 처리와 맞는지 확인한다.
4. T4 다중 교통 검색의 안내전용 후보를 화면과 음성 Function에서 운행 생성으로 넘기지 않는다. 기존 create_trip 공개 계약을 무심코 넓히지 않고 서버에 명시적으로 온 unsupported metadata도 거절한다. 검색기록 검증 저장소가 없다는 한계를 과장해서 보완됐다고 기록하지 않는다.
5. 후보 안내/무인자 정규화/노선 발음/적응형 도착 조회가 T4와 T5 공유 상수 변경 이후 유지되는지 확인한다.
6. CI 검사 명령은 실제 실행할 수 있어야 하며 DB fixture는 실제 service_role 의미를 재현한다. Node 최소 요구, server main 산출물, lint·전체 스크립트·C++·SQL 검사가 문서와 맞아야 한다.

보고: spec/quality 각각 APPROVE 또는 구체적 재현/파일/영향/수정 방향. 미실행 실제 기기·배포 검증은 별도 한계로 둔다. 코드 수정, 커밋, 푸시는 하지 않는다.
